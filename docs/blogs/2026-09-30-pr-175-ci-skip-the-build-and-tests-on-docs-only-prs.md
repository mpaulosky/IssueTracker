# ci: Skip the build and tests on docs-only PRs

- **Release tag:** `v0.0.14`
- **Source PR:** [#175](https://github.com/mpaulosky/IssueTracker/pull/175)

## PR description

### Summary

Every release blog PR changes only documentation (`docs/blogs/`, `README.md`, `docs/README.md`), yet ran the full build, all eight test projects, coverage and CodeQL: about **17 runner-minutes** each (#167, #169, #171). `paths-ignore` can't skip them, because `Build Solution` and `Test Suite` are required checks, and a check that never reports blocks the merge.

- **New `Detect Changes` job** (`ci.yml`) classifies the PR's changed files. When every one is Markdown or under `docs/`, `Build Solution`, the test matrix and coverage are **skipped**. GitHub counts a required check skipped by its `if:` as passing, and `pr-automerge.yml` relies on GitHub's `CLEAN` merge state, which does the same.
- **Fails safe:** any other path (workflows, scripts, `.cs`, project files) runs the full suite, as do pushes and manual runs. An empty diff runs it too. Renames are listed under both paths (`--no-renames`), so moving code into `docs/` or to a `.md` name still runs the suite.
- **`Test Suite` stays honest:** it still fails on any failed or cancelled job, and also when `Detect Changes` itself didn't succeed, so the build can't be skipped by mistake. On a docs-only PR its summary says the build and tests were skipped.
- **CodeQL** ignores `docs/**` and `**/*.md` on `pull_request`. It isn't a required check, and `main`'s push and weekly runs still cover the code.
- Lint Markdown, YAML and Actions, and the Python and hook tests, still run on every PR.

### Testing

- The classification was run in a scratch repo (and `--no-renames` confirmed to list both paths when `src/a.cs` is moved to `docs/a.md`): a blog-PR-shaped change and `docs/index.html` → docs-only. A `.cs` file, a workflow, Markdown plus code, a file named `docs.md.cs`, and an empty diff → full suite.
- `yamllint`, `actionlint` and `zizmor` are clean, and `scripts/gate.sh` passed.
- This PR changes workflows, so its own CI takes the full-suite path.
- The docs-only path was checked live on a throwaway draft PR that changes one doc and targets this branch (see the comments), before this PR was marked ready.
