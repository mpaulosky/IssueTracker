# fix(sandcastle): Close the last gaps in the host's config guard and secret scan

- **Release tag:** `v0.0.47`
- **Source PR:** [#244](https://github.com/mpaulosky/IssueTracker/pull/244)

## PR description

### Why

PR Auto-Merge merged #242 before Claude Review finished with its final head. That review opened six threads on the hardening #242 added, and all six are real:

- **A config change found while publishing was swallowed.** It turned into a `publish-failed` comment, and `sandbox.close()` still ran Sandcastle's git under the changed config. That also happened when another pipeline's agent changed the config after this pipeline's last host git call.
- **The secret scan could miss added lines.** It skipped every line starting with `+++ `, which also drops an added line whose content starts with `++ `. It didn't scan file paths. With a user's `color.diff=always`, it saw no added lines at all.
- **Replace refs could hide content.** `refs/replace` sits in the same writable `.git`, and `git log`/`diff`/`rev-list` honour it, but a push sends the real objects.
- **`ls-remote origin refs/heads/main` could pick another branch.** It also matches a branch like `feature/refs/heads/main`, which sorts first.
- **The check-file warning could still be dodged.** `discover_tests.py` and `needs-docker.sh` read whole XML documents. A <code>&#60;&#33;&#45;&#45;</code>/`-->` pair or a `Condition` on its own line can drop a test project without changing any line the pattern matches.

### What changed

- **`lib/build.mts`, `lib/shell.mts`:** the publish step rethrows `GitConfigChangedError`. `finally` checks the config again before it closes the sandbox, and throws `GitConfigChangedError` if it changed, whatever the pipeline returned (published, rejected, nothing to publish). The throw replaces the return value, so `main.mts` stops the run before Sandcastle's own git runs under the changed config.
- **`lib/scan.mts`:** `addedLines` reads the patch with state. File headers run until a hunk header, and the number of `@`s gives the number of parent columns. A line is added when one of its columns is `+` and none is `-`, so an added `++ token` line is scanned. Header lines, and so the paths, are scanned too. `git log` gets `--no-color`. The commits are read with `--format=raw` rather than `%B`, so the author and committer names and emails, `encoding`, `gpgsig` and any extra header, which the push publishes too, are scanned.
- **`lib/shell.mts`:** `HOST_GIT_CONFIG` adds `core.useReplaceRefs=false` for every git on the host, Sandcastle's included. The `git()` helper also passes `-c core.useReplaceRefs=false` itself, so the scan and the check-file warning hold up without `protectHostGit`.
- **`lib/branches.mts`:** `mainCommit` keeps only the exact `refs/heads/main` line, and throws unless there is exactly one.
- **`lib/check.mts`, `CODING_STANDARDS.md`:** every change is named for the MSBuild files under `tests/` and every `Directory.Build.*` file at any depth. The pathspecs carry explicit `:(glob)` magic (`:(glob)**/Directory.Build.*` and so on), so they match nested files under a host's `GIT_GLOB_PATHSPECS=1` too. The keyword pattern still covers MSBuild files elsewhere.

### Verification

- `pnpm run test:sandcastle`: the type check is clean and 109 of 109 tests pass. New tests cover a config change found during publish and one found at the end of a pipeline that published, was rejected or had nothing to publish (each rejects with `GitConfigChangedError` and leaves the sandbox open), tokens in an author name and a committer email, a replace ref hiding a token and a check-file change (with and without `protectHostGit`, plus a control), nested `tests/Directory.Build.props` and `src/X/Directory.Build.targets` changes with and without `GIT_GLOB_PATHSPECS=1`, an added line that looks like a header, a scan with `color.ui=always`, an ls-remote result with a decoy branch, and a test project commented out on lines of their own plus a `Directory.Build.props` change.
- The pre-push gate passed.

Its final Claude Review round opened four threads; all four are fixed here, and `review:claude` is off.
