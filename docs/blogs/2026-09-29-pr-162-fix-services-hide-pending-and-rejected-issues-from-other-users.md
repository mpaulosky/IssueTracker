# fix(Services): Hide Pending and Rejected Issues from other Users

- **Release tag:** `v0.0.8`
- **Source PR:** [#162](https://github.com/mpaulosky/IssueTracker/pull/162)

## PR description

### Summary

`/Details/{Id}` and `/Comment/{Id}` loaded any Issue by ID, so a signed-in User who knew or guessed an ID could read a Pending or Rejected Issue that the lists only show to its Author and the Admins.

- `IssueService.GetIssue(issueId, viewerId, viewerIsAdmin)` returns `null` for a Pending or Rejected Issue unless the viewer is its Author or an Admin, and for an Issue that doesn't exist. A hidden Issue is indistinguishable from a missing one (not-found, not forbidden).
- Both pages decide Admin through the existing `"Admin"` authorization policy (the same one `AuthorizeView` uses) and show the app's not-found message on `null`; Details skips loading comments.
- `CONTEXT.md`: a Pending Issue is now described as visible only to its Author and the Admins.

Archived Issues are unchanged and still reachable by ID; that's outside this issue.

### Testing

- New service tests: other User denied for Pending and Rejected, Author and Admin allowed, Approved visible to all, unknown ID, and an empty viewer id can't match an Issue with no Author. With the check removed, 4 of them fail.
- New bUnit page tests (`BunitContext`) for the not-found view and allowed viewers on both pages.
- `IssueTracker.Services.Tests.Unit` 82 passed, `IssueTracker.UI.Tests.Unit` 148 passed; `scripts/gate.sh` passed.
