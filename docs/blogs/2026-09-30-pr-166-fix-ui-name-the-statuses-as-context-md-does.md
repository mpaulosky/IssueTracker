# fix(UI): Name the Statuses as CONTEXT.md does

- **Release tag:** `v0.0.10`
- **Source PR:** [#166](https://github.com/mpaulosky/IssueTracker/pull/166)

## PR description

### Summary

First half of #152 (the `ApprovedForRelease` → `Approved` rename follows in its own PR).

The glossary names the Statuses **Accepted, Watching, Upcoming, Dismissed**, but the code used three sets:

- `SampleData` seeded Answered, Watching, Upcoming, Dismissed.
- The Set Status buttons, the status CSS classes, `FakeStatus` and `Enums.Status` used Answered, InWork, Watching, Dismissed, so on a seeded database the "in work" button looked up a Status that didn't exist and threw.

Now:

- Everything uses Accepted, Watching, Upcoming, Dismissed: seed data, `FakeStatus`, `Enums.Status` (kept, since `FakeStatus` picks from it; members keep their positions), `IssueComponent`'s status styles, and the Set Status buttons (ids, labels, CSS classes). `site.css` classes are renamed to match.
- The seeded Status descriptions and the Create page say "issue" instead of "suggestion".

### Existing data

`scripts/migrations/152-rename-answered-status.js` renames `Answered` Status records to `Accepted`, updates each Issue's embedded copy (`IssueStatus.StatusName`), and rewords seeded descriptions that still say "suggestion" (an Admin's own wording is left alone). It can safely be run more than once. Run it once per environment after this merges:

```bash
mongosh "<connection string>/<database>" scripts/migrations/152-rename-answered-status.js
```

Tested twice against a throwaway `mongo:8` container: the first run renamed and reworded, the second changed nothing.

### Testing

- UI tests updated to the new names (18 failed before the source change); `IssueTracker.UI.Tests.Unit` 148, CoreBusiness 86, Services 99, PlugIns 37 passed.
- `scripts/gate.sh` passed.
