# ci: Drop the unused build-artifact cache

- **Release tag:** `v0.0.15`
- **Source PR:** [#178](https://github.com/mpaulosky/IssueTracker/pull/178)

## PR description

### Summary

Item 3 of #144. The build job saved `bin/` and `obj/` to a cache that no job ever restored, because every test job restores and rebuilds its own project. This removes that step and leaves a comment on the test job explaining why the matrix rebuilds.

### How the option was chosen

Each option ran 3 times by `workflow_dispatch`, one run at a time, on its own branch:

| Option | Passed | Wall clock (avg, range) | Runner-minutes (avg) |
| --- | --- | --- | --- |
| `main` as it was | 3/3 | 3.7 min (3.2–4.0) | 10.6 |
| **Rebuild per project, no cache step (this PR)** | 3/3 | **2.9 min (2.8–3.2)** | 10.2 |
| Share the build output, tests with `--no-build` | 3/3 | 3.8 min (3.7–3.9) | 10.3 |
| One test job running every project | 3/3 | 4.4 min (4.0–4.8) | **4.2** |

- **Sharing the build** saved nothing. Packing the 164 MB of build output costs about 20s in the build job, and downloading and unpacking it about 9s per test job. The test jobs still need the NuGet cache and a restore, because `--no-build` skips compiling but the test host and Blazor static web assets still load files from `.nuget/packages`; its first run failed without them.
- **One test job** uses 60% fewer runner-minutes, because it pays the per-job setup (checkout, .NET, NuGet cache, restore) once instead of 8 times. It's about 1.5 minutes slower, though, and minutes are free for a public repository.
- Most of the cost in every matrix option is that per-job setup, not the build, which takes about 15s.

### Testing

- `yamllint`, `actionlint` and `zizmor` are clean, and `scripts/gate.sh` passed.
- The option-A branch passed 3 of 3 full CI runs in the experiment.
