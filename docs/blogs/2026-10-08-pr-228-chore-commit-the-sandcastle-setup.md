# chore: Commit the Sandcastle setup

- **Release tag:** `v0.0.39`
- **Source PR:** [#228](https://github.com/mpaulosky/IssueTracker/pull/228)

## PR description

### Why

`.sandcastle/` and the `package.json` that installs `@ai-hero/sandcastle` were never committed, so a fresh clone can't run Sandcastle and prompt changes go unreviewed. Sandcastle expects the folder to be committed, with only its generated files ignored. Blazor-Server already works this way.

As generated, the setup also didn't fit this repo. The image had no .NET SDK. The prompts verified with npm scripts that don't exist. Branch names failed the branch standard, and commits used a `RALPH:` prefix instead of Conventional Commits. This PR fixes those problems too.

### What changed

- **The Sandcastle setup is committed:** `.sandcastle/` holds the `Dockerfile`, `main.mts`, the `*-prompt.md` files, `CODING_STANDARDS.md`, `.env.example` and Sandcastle's `.gitignore` (which ignores `.env`, `logs/` and `worktrees/`). `package.json` and `pnpm-lock.yaml` pull in `@ai-hero/sandcastle` and `zod`. `.sandcastle/.markdownlint-cli2.jsonc`, copied from Blazor-Server, turns off MD025 and MD033 for the prompts.
- **The sandbox image can build the repo:** it installs the latest .NET 10 SDK (global.json pins 10.0.401 with `rollForward: latestMinor`) and libicu72. It also adds python3, yamllint and shellcheck for `scripts/gate.sh`, and enables pnpm through corepack.
- **pnpm, not npm:** the sandbox hook runs `pnpm install --frozen-lockfile`. `package.json` pins `pnpm@12.6.0` in `packageManager` (pnpm records this in the lockfile) and refuses npm. `pnpm sandcastle` starts the loop.
- **Branch names follow the standard:** the host names each branch in `.sandcastle/lib/branches.mts`, never the model. A bug gets <code>hotfix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code> and every other issue gets <code>feature&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>, with the slug taken from the issue title. An issue's existing branch is reused. `pnpm test:sandcastle` runs the tests, and one of them checks names against `scripts/check-branch-name.sh`.
- **The prompts verify with .NET:** the implement, review and merge prompts run `dotnet build IssueTracker.slnx -c Release -warnaserror` and `dotnet test` once per test project. They skip the three test projects that need Docker, because the sandbox has none; CI still runs those.
- **Conventional Commits:** the prompts tell the agents to write <code>&#60;type&#62;&#40;&#60;scope&#62;&#41;&#58; &#60;Summary&#62;</code> instead of using the `RALPH:` prefix.
- **`CODING_STANDARDS.md`** used to hold placeholders. It now points the reviewer at `CLAUDE.md`, `.editorconfig`, `.github/instructions/` and `docs/PROCESS.md`, and lists the rules reviewers most often have to flag.
- **The license is MIT** in `package.json`, matching the repo. It was ISC.

### Verification

- markdownlint reports 0 issues across the `.sandcastle/` Markdown files.
