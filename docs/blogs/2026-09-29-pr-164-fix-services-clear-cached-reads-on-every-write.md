# fix(Services): Clear cached reads on every write

- **Release tag:** `v0.0.9`
- **Source PR:** [#164](https://github.com/mpaulosky/IssueTracker/pull/164)

## PR description

### Summary

Several service write paths left `IMemoryCache` entries in place, so pages showed old data until they expired (a minute for Issues and Comments, a day for Statuses).

- `StatusService`: `CreateStatus`, `UpdateStatus` and `DeleteStatus` now remove `StatusData` (only `ArchiveStatus` did).
- `CommentService`: `CreateComment` now removes `CommentData`.
- `IssueService`: `CreateIssue`, `UpdateIssue` and `ArchiveIssue` remove both `IssueData` and the Author's own list, which `GetIssuesByUser` caches under the Author's Id and nothing evicted before. A `RemoveCachedIssues` helper does both.
- Every eviction now runs after the repository write, so a read in between can't re-cache the old data. That also moves the existing evict-before-write calls in `ArchiveIssue`, `ArchiveStatus`, `ArchiveComment` and all three `CategoryService` writes (Copilot review), each with a call-order test.
- `CLAUDE.md` no longer describes the gap as open. `CategoryService` already evicted on every write; `UserService` doesn't cache.

### Testing

- One test per write method (11) asserting its evictions; before the fix, exactly the 7 methods missing an eviction failed. Six call-order tests fail if an eviction precedes its write.
- `IssueTracker.Services.Tests.Unit` 99 passed, `IssueTracker.UI.Tests.Unit` 148 passed; `scripts/gate.sh` passed.
