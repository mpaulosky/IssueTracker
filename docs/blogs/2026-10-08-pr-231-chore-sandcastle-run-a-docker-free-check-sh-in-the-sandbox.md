# chore(sandcastle): Run a Docker-free check.sh in the sandbox

- **Release tag:** `v0.0.43`
- **Source PR:** [#231](https://github.com/mpaulosky/IssueTracker/pull/231)

## PR description

### Why

Sandcastle's sandbox gets no Docker on purpose: mounting the host's Docker socket would give the agents root on the host, and they read public issue content. Until now the implement, review and merge prompts told agents to build, then pick test projects by hand and skip three named as needing Docker (`Integration.Tests`, `IssueTracker.PlugIns.Tests.Integration`, `AppHost.Tests`). That list was wrong: only `IssueTracker.PlugIns.Tests.Integration` starts containers. `Integration.Tests` uses an in-memory cache, and `AppHost.Tests` builds Aspire models without starting them, so both run without Docker and were being skipped for nothing.

### What changed

- **`.sandcastle/check.sh`** is the one check for the sandbox. It runs yamllint and shellcheck over the files CI lints, then builds `IssueTracker.slnx` in Release with `-warnaserror`. Next it runs `dotnet test` on every test project CI's `discover_tests.py` finds, except the ones that need Docker, and finally runs `pnpm run test:sandcastle`. A project needs Docker when it uses Testcontainers, `Aspire.Hosting.Testing` or Playwright, either directly or through `tests/` projects it references (at any depth), or when it sets <code>&#60;RequiresDocker&#62;true&#60;&#47;RequiresDocker&#62;</code> because it starts containers some other way. The skip list comes from those references, so a new Docker-backed suite is skipped without anyone editing a list. The rule lives in `.sandcastle/needs-docker.sh`, which ignores XML comments and has its own fixture tests in `.sandcastle/lib/needs-docker.test.mts`.
- **Prompts:** `implement-prompt.md`, `review-prompt.md` and `merge-prompt.md` now run `.sandcastle/check.sh` instead of the hand-picked commands. They say the host's pre-push gate and CI run the Docker suites, and that agents must not try to start Docker.
- **`CODING_STANDARDS.md` and `CLAUDE.md`** describe the check, explain why the sandbox has no Docker, and say which suites need Docker and who runs them. Nothing on the host runs `check.sh` yet, so it is advisory, and the docs say so: the pre-push gate and CI are what hold a broken branch back.
- **Sandbox linters at CI's versions:** the Dockerfile installs shellcheck v0.11.0 (the release binary, sha256-verified, matching `lint-actions.yml`) and yamllint 1.38.0, instead of Debian bookworm's 0.9.0 and 1.29.
- **`tests/ServiceDefaults.Tests`:** removed an unused `Testcontainers` reference (no code uses it), so the package rule doesn't skip a suite that needs no Docker.
- **`test:sandcastle` in the gate and CI:** the new `.github/ci/sandcastle-tests.sh` runs the Sandcastle tests (`node --run test:sandcastle`, which needs no pnpm or corepack) when `.sandcastle/`, `package.json`, `pnpm-lock.yaml` or `scripts/check-branch-name.sh` (which the tests run) changed. `.github/ci/gate-checks.sh` (pre-push) and `.github/ci/prepare.sh build` (CI's Build Solution job) both call it. It fails with a clear message on a Node older than 22.18, since `ci.yml` is Owned by the Template and sets up no Node.
- **`prepare.sh test`** no longer publishes the UI or pulls the Mongo and Redis images for `AppHost.Tests`, which never starts the app.

`main.mts` has no completion gate of its own, so nothing there changed.

### Verification

- Built the sandbox image from `.sandcastle/Dockerfile` (shellcheck 0.11.0, yamllint 1.38.0) and ran `pnpm install --frozen-lockfile && .sandcastle/check.sh` in it against this branch, with no Docker socket. It exited 0: the lints were clean and the build had 0 errors. All 8 Docker-free projects passed (AppHost 33, Architecture 4, Integration 11, CoreBusiness 87, PlugIns.Unit 37, Services 99, UI 148, ServiceDefaults 12), `IssueTracker.PlugIns.Tests.Integration` was skipped as needing Docker, and the Sandcastle tests passed 11/11. Since then, check.sh passes on the final head with 22/22 Sandcastle tests, counting the new needs-docker tests and one main added.
- Before writing the rule, I ran every test project in that image without Docker. Only `IssueTracker.PlugIns.Tests.Integration` failed.
- The host pre-push gate passed, including all 9 test projects and the new Sandcastle step.
