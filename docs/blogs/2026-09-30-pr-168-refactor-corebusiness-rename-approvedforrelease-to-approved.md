# refactor(CoreBusiness): Rename ApprovedForRelease to Approved

- **Release tag:** `v0.0.11`
- **Source PR:** [#168](https://github.com/mpaulosky/IssueTracker/pull/168)

## PR description

### Summary

Second half of #152 (the Status names landed in #166).

`CONTEXT.md` defines **Approval** as an Admin's decision that an Issue may be shown to every User, not that it ships in a release.

- `IssueModel.ApprovedForRelease` is now `Approved`, across CoreBusiness, PlugIns, Services, UI and the tests.
- Its doc comments, and those on `GetApprovedIssues` in `IIssueService` and `IIssueRepository`, now describe it that way.
- It is still stored as `approved_for_release` (`[BsonElement]`, as before), so existing data needs **no migration**.

### Testing

- New `IssueModelTests` test: an approved Issue serializes with `approved_for_release: true` and no `Approved` element, so a future rename can't silently change the stored field.
- CoreBusiness 87, Services 99, PlugIns 37, UI 148 passed; `dotnet build -warnaserror` clean; `scripts/gate.sh` passed.
