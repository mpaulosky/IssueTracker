# fix(sandcastle): Close the gaps Claude Review found after #236 merged

- **Release tag:** `v0.0.46`
- **Source PR:** [#242](https://github.com/mpaulosky/IssueTracker/pull/242)

## PR description

### Why

#236 replaced Sandcastle's local merger with one draft PR per issue. PR Auto-Merge merged it after its review cap, and Claude Review's pass over its final head then opened six threads. All six hold up:

- **Agent-edited hooks could still run on the host.** #236 turned hooks off only for the host's own git. Sandcastle runs `git worktree add` on the host too. That runs `post-checkout` from the new worktree, which is the branch's copy of `.github/hooks`, and a branch can be one the agents wrote in an earlier run.
- **Detected config tampering didn't stop the run.** A `GitConfigChangedError` was logged as one failed issue. `sandbox.close()` still ran Sandcastle's git under the tampered config, and the run could end with "All done."
- **Pushed commits were never checked for the sandbox's secrets.** The Claude token or API key is in the sandbox, and an agent could commit it in a log, fixture or snapshot.
- **The PR warning missed most ways to skip a test project.** Only a `RequiresDocker` change was flagged. A Docker-backed package, `IsTestProject=false`, a `ProjectReference`, or a deleted test project slipped through. The comparison also used `origin/main`, a ref the agents can move.
- **Issue titles could close other issues.** A title like "Fix #12 regression" went unchanged into the PR title (the squash subject) and the body.
- **Stopped issues vanished from the planner.** An issue that stopped earlier in a run was in neither of the planner's lists, so the issues it blocks looked unblocked.

### What changed

- **`lib/shell.mts`, `main.mts`:** `protectHostGit()` runs first. It adds `core.hooksPath=/dev/null` and `core.fsmonitor=false` through `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n`, after any entries already there. Every git process on the host inherits these, Sandcastle's included. They don't reach the sandbox: Sandcastle passes it only what `.sandcastle/.env` names.
- **`lib/build.mts`, `main.mts`:** if a pipeline hits `GitConfigChangedError`, it leaves its sandbox open and rethrows. `main.mts` rethrows the first such error after the round, so the run exits non-zero with the warning.
- **`lib/scan.mts`, `lib/build.mts`, `lib/sandbox-env.mts`:** before the push, the host scans what it would publish, from main's commit to the checked commit. That is every commit message and every added line, from `git log -p --cc -U0`, so merge commits are read too. Context and removed lines are left out, so main's fake test tokens don't stop unrelated branches. The scan looks for the values `.sandcastle/.env` gives the sandbox and for Claude and GitHub token shapes. A match stops the issue as `secret-in-commits`, with a comment that doesn't quote it.
- **`lib/check.mts`:** the warning now covers MSBuild lines matching `RequiresDocker|IsTestProject|Testcontainers|Aspire.Hosting.Testing|Playwright|ProjectReference`, and files deleted or renamed away under `tests/`.
- **`lib/branches.mts`, `lib/build.mts`:** `fetchMain()` returns main's commit as `git ls-remote origin` reports it. The merge, `commitsAhead`, the warning and the secret scan all compare with that commit id, not with `refs/remotes/origin/main`.
- **`lib/publish.mts`:** `withoutClosingKeywords` now also rewrites the issue title, in the PR title and body, and full `github.com/.../issues/n` and `/pull/n` URLs.
- **`lib/prompts.mts`, `plan-prompt.md`:** the planner's second list is now the held-back issues (<code>&#123;&#123;HELD&#95;BACK&#95;JSON&#125;&#125;</code>), both in review and stopped earlier in the run, and they count as blockers.

### Verification

- `pnpm run test:sandcastle`: the type check is clean and 99 of 99 tests pass. The new tests run against real temp repositories: a `git worktree add` with `protectHostGit` doesn't run a `post-checkout` hook, and the same command without it does. `checkFileChanges` flags a Testcontainers reference, `IsTestProject=false`, a deleted test project, a renamed test file and `check.sh`, but not an ordinary `src/` package change. `publishedText` sees a secret added in a merge resolution, but not a fixture token in context. Other new tests cover the secret stop, the untouched sandbox on config tampering, and closing references in titles and URLs.
- The pre-push gate passed.
