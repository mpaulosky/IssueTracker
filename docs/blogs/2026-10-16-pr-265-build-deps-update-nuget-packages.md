# build(deps): Update NuGet packages

- **Release tag:** `v0.0.57`
- **Source PR:** [#265](https://github.com/mpaulosky/IssueTracker/pull/265)

## PR description

_Requested by **Matthew** · [project thread](https://claude.ai/code/project/chan_01M4TRjuaTvMLM1jqeNd9KNs?thread=cmsg_01M4TRjuaTvMLM1jqeNd9KNs3RNc9yDo6fauxomeH8GaE4)_

### Why

Several NuGet packages had newer stable releases, and the Aspire versions had drifted apart: the `Aspire.AppHost.Sdk` was on 13.4.6 while the Aspire hosting packages were on 13.6.0. This brings everything up to the latest stable versions and puts all of Aspire on 13.6.1.

### What changed

Package versions in `Directory.Packages.props`, plus the SDK version in `src/AppHost/AppHost.csproj`:

- Aspire.AppHost.Sdk 13.4.6 → 13.6.1
- Aspire.Hosting, Aspire.Hosting.AppHost, Aspire.Hosting.MongoDB, Aspire.Hosting.Redis 13.6.0 → 13.6.1
- AngleSharp 1.8.2 → 1.8.5
- Microsoft.AspNetCore.Authorization, .Components, .Components.Forms, .Components.Web, .Mvc.Testing 10.0.12 → 10.0.13
- Microsoft.Extensions.Caching.Abstractions, .Caching.StackExchangeRedis, .Configuration.UserSecrets, .DependencyInjection, .Diagnostics.HealthChecks, .Options 10.0.12 → 10.0.13
- Microsoft.Identity.Web, Microsoft.Identity.Web.UI 4.16.0 → 4.16.1
- Microsoft.Testing.Extensions.CodeCoverage 18.11.2 → 18.12.0
- OpenTelemetry, .Exporter.Console, .Exporter.OpenTelemetryProtocol, .Extensions.Hosting 1.19.1 → 1.20.0
- OpenTelemetry.Instrumentation.AspNetCore, .Http, .Runtime 1.19.0 → 1.20.0
- SharpCompress 0.50.4 → 0.50.5 (the newest 0.x; MongoDB.Driver 3.12.0 is built against the 0.x line, so 1.0.0 would risk runtime binding errors)
- StackExchange.Redis 3.3.1 → 3.4.5
- Testcontainers, Testcontainers.MongoDb, Testcontainers.Redis 4.15.0 → 4.16.0
- xunit.v3 4.0.1 → 4.0.2
- Major versions, which build and pass the tests with no code changes:
  - Ardalis.GuardClauses 4.0.1 → 5.0.0
  - Microsoft.CodeAnalysis 4.6.0 → 5.9.0
- Removed the `Aspire.Dashboard` 13.4.6 pin: no project references it (the AppHost SDK brings its own dashboard packages).

Both Ardalis.GuardClauses and Microsoft.CodeAnalysis are used only by `src/PlugIns/IssueTracker.PlugIns.Mongo`, which isn't in `IssueTracker.slnx`, so CI doesn't build it. It builds on its own with `-warnaserror` on the new versions.

Not updated:

- **Radzen.Blazor stays on 7.4.3.** On 12.1.4 the solution builds, but all 16 bUnit tests of the Categories and Statuses pages fail: `RadzenDataGrid` now calls `Radzen.createDataGrid` through JS interop, which the tests don't set up. Moving up five major versions of UI components needs its own PR, with the tests updated and the pages checked in a browser.
- MessagePack stays on 2.5.307, the newest 2.x, which is the security pin for Aspire's transitive 2.x dependency.
- FluentAssertions stays pinned at <code>&#91;8&#46;11&#46;0&#93;</code>, which is already the latest.

One test fix: `ArchiveUserTests` had stray <code>&#91;Fact&#93;</code> attributes on its `IAsyncLifetime` `InitializeAsync` and `DisposeAsync` methods. The integration test run reported both as failed tests (xUnit1024, overloaded test methods), so I removed the two attributes.
