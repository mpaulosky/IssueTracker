# fix(release): Skip a named PR merged elsewhere; mark a published draft

- **Release tag:** `v0.0.18`
- **Source PR:** [#184](https://github.com/mpaulosky/IssueTracker/pull/184)

## PR description

### Summary

Two flaws in the release pipeline (#172), found by Copilot's review of its port to atelier-store (mpaulosky/atelier-store#90). This keeps IssueTracker, the reference implementation, in step.

- **A manual run naming a PR merged elsewhere:** `release_queue.py` queued the named PR without checking its base branch, so a PR merged into another branch failed the run with `UnknownMergeOrder` (its merge commit isn't on `main`). Only a named PR whose base is `main` is queued now.
- **Publishing a draft Release:** the release job published a draft for its tag without touching its body. The planner and the ordering guard recognise a Release only by its `Source PR: #n` marker, so a draft without one stayed "owed" forever and blocked every later PR. The decision now lives in a tested helper, `.github/scripts/draft_release.py`: it appends the release notes unless the draft already names this PR on a line of its own (LF or CRLF), keeping the draft's own text. A draft that names a *different* PR is inconsistent, so the step stops with an error naming it rather than publish a Release with two sources. Markers count anywhere in a line, the pattern `release_post.source_pr_of()` uses, so a `- Source PR: #5` list item is caught too.

### Testing

- New `test_main_skips_a_manually_named_pr_merged_into_another_branch` (it failed before the fix).
- New `test_draft_release.py` (17 tests): no marker, an empty draft, this PR's line (also with CRLF endings), this PR only inside a longer line, another PR (alone, in a list item, or beside this PR's line), `#5` against `#15` and `#50`, agreement with `source_pr_of()`, and the CLI's output and stderr error.
