# ci(automerge): Re-check a PR when a review is submitted

- **Release tag:** `v0.0.26`
- **Source PR:** [#201](https://github.com/mpaulosky/IssueTracker/pull/201)

## PR description

PR Auto-Merge re-checks a PR when a CI workflow completes, or on its 15-minute schedule. When Copilot's review is the last thing a PR is waiting on, it usually arrives after CI has finished, so the PR waits for the schedule. GitHub only ran that schedule every one to two hours (15:23, 13:37, 11:34 UTC today). #197 waited, and I had to start the sweep by hand.

### Change

- **New `pr-review-submitted.yml`**: runs on `pull_request_review: submitted` with `permissions: {}` and does nothing else. It exists so its completion can trigger PR Auto-Merge.
- **`pr-automerge.yml`**: adds `PR Review Submitted` to its `workflow_run` list. The merge decision still runs main's copy of the script with write access, never the PR's, which is why this doesn't use `pull_request_review` directly.
- **Schedule**: the sweep stays, because resolving a review thread has no Actions trigger. It moves from `*/15` to `7,22,37,52`: GitHub drops the most scheduled runs at the top of the hour and on round minutes.

### Verification

- `yamllint`, `actionlint` and `zizmor` are clean locally, and `scripts/gate.sh` passed on push.
- `workflow_run` only picks up the new workflow once it's on `main`, so this PR can't exercise it. The first PR after it merges will show whether Copilot's review triggers a run of `PR Review Submitted` and then PR Auto-Merge.
