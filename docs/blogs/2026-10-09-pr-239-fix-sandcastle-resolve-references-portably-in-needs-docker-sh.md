# fix(sandcastle): Resolve references portably in needs-docker.sh

- **Release tag:** `v0.0.44`
- **Source PR:** [#239](https://github.com/mpaulosky/IssueTracker/pull/239)

## PR description

### Why

PR Auto-Merge merged #231 before the fix for its last two Claude Review findings was pushed. This PR lands that fix.

- `.sandcastle/needs-docker.sh` resolved project references with `realpath -m --relative-to`. Both flags are GNU-only, so on macOS the script failed. The pre-push gate's Sandcastle tests failed with it, and the gate refused any push touching `.sandcastle/`.
- The "doesn't need Docker" tests in `needs-docker.test.mts` passed on any non-zero exit, so a crashing script also passed them.

### What changed

- `needs-docker.sh` normalises reference paths with `python3 -I` and `os.path.relpath(os.path.normpath(...))`. No GNU-only flags remain, and python3 is already a gate dependency through `discover_tests.py`.
- Every "no" case in `needs-docker.test.mts` now requires exit 1 with an empty stderr.

### Verification

- `node --run test:sandcastle`: 22/22 pass.
- `.sandcastle/check.sh` exits 0. It skips only `IssueTracker.PlugIns.Tests.Integration`.
- The pre-push gate passed.
