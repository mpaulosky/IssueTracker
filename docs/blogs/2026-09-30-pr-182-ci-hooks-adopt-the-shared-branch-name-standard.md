# ci(hooks): Adopt the shared branch-name standard

- **Release tag:** `v0.0.17`
- **Source PR:** [#182](https://github.com/mpaulosky/IssueTracker/pull/182)

## PR description

### Summary

Every repo now uses one branch-name rule. The eight repos with git hooks had five different rules between them.

| Branch | Use |
| --- | --- |
| `feature/{issue}-{slug}` | New behaviour |
| `fix/{issue}-{slug}` | A bug fix (new prefix) |
| `hotfix/{issue}-{slug}` | An urgent fix |
| `chore/{slug}` | Work without an issue |

A slug is lowercase letters and digits in words joined by `-`; a `chore/` slug starts with a letter, so it can't pass for an issue-linked name. `squad/` and `sprint/` are retired along with the squad setup.

- `.github/hooks/pre-push` enforces the standard and names it in its error message.
- `.github/hooks/tests/pre-push.test.sh`: each accepted prefix runs the gate, slugs with digits are accepted (`chore/upgrade-net10`, `feature/8-oauth2-login`), and `squad/`, `sprint/`, prefixes missing an issue number, uppercase slugs, and a `chore/` slug starting with a digit are refused.
- `CLAUDE.md` lists the standard.

The other repos adopt it through the `repo-ci-baseline` skill's git-hooks part.

### Testing

- `pre-push.test.sh`: 47 cases pass. Before the hook changes, 4 failed: `fix/` was refused, and `squad/`, `sprint/` and `chore/7-cleanup` were accepted.
- `shellcheck` and `markdownlint` are clean, and the pre-push gate passed.
