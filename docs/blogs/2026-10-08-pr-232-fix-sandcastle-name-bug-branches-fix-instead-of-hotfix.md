# fix(sandcastle): Name bug branches fix/ instead of hotfix/

- **Release tag:** `v0.0.41`
- **Source PR:** [#232](https://github.com/mpaulosky/IssueTracker/pull/232)

## PR description

### Why

Sandcastle named the branch for a `bug` issue <code>hotfix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>, a mapping copied from Blazor-Server. In this repo, docs/PROCESS.md makes <code>fix&#47;&#123;issue&#125;&#45;&#123;slug&#125;</code> the branch for a bug fix and keeps <code>hotfix&#47;&#123;issue&#125;&#45;&#123;slug&#125;</code> for an urgent fix. No label marks an issue as urgent, so Sandcastle has no way to tell one apart and should never pick `hotfix/` itself.

### What changed

- `.sandcastle/lib/branches.mts`: a `bug` issue now gets <code>fix&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>; every other issue still gets <code>feature&#47;&#123;n&#125;&#45;&#123;slug&#125;</code>.
- Finding an issue's earlier work (`isIssueBranch` and `localIssueBranches`) now recognizes `feature/`, `fix/` and `hotfix/` branches, so a branch already in flight under any of them is reused rather than orphaned.
- `.sandcastle/lib/branches.test.mts`: the bug case expects `fix/`, `isIssueBranch` is checked for `fix/`, and a new test covers reusing an existing `fix/` or `hotfix/` branch. The existing test that runs every generated name through `scripts/check-branch-name.sh` still covers both labels.

No prompt text names `hotfix/`, so the prompts are unchanged.
