# fix(AppHost): Start the AppHost again on Aspire 13.5

- **Release tag:** `v0.0.25`
- **Source PR:** [#197](https://github.com/mpaulosky/IssueTracker/pull/197)

## PR description

`dotnet run --project src/AppHost` failed at startup with
`OptionsValidationException: A health check registration is missing`.

### Why

`AddMongoDBWithManagement` and `AddRedisCache` called `.WithHealthCheck(name)`. That doesn't add a check: it requires one registered under that key, and nothing registered `mongodb` or `redis`. Aspire 13.5 validates this when the host starts. `AddMongoDB` and `AddRedis` already register and attach their own checks, so the calls are removed and both resources keep a health check.

Once that was fixed, startup failed next on the `http` launch profile, which neither allowed unsecured transport nor named the dashboard's OTLP and resource service endpoints. The profile now sets `ASPIRE_ALLOW_UNSECURED_TRANSPORT`, `ASPIRE_DASHBOARD_OTLP_ENDPOINT_URL` and `ASPIRE_RESOURCE_SERVICE_ENDPOINT_URL`, as Aspire's template does.

### Tests

- Two new `AppHost.Tests` resolve `HealthCheckServiceOptions` after adding each resource. Both failed with the original exception before the fix.
- `AppHost.Tests` 33/33, and `scripts/gate.sh` passed on push.
- Ran the AppHost locally: the dashboard, MongoDB, Redis and the UI start.
