# docs: Write agent guidance for IssueTracker

- **Release tag:** `v0.0.3`
- **Source PR:** [#146](https://github.com/mpaulosky/IssueTracker/pull/146)

## PR description

### Summary

Replaces two sets of guidance that didn't describe this repo: the Copilot-era instructions, which described a "TailwindBlogApp" solution, and the files copied from atelier-store, which describe a storefront.

**New**
- **`CLAUDE.md`** at the root covers:
  - the layers and how they connect (the UI calls services only; `Extensions/` is the composition root)
  - build, run and test commands, and why the SDK is pinned to 10.0.3xx
  - test conventions and code style
  - the branch → PR → auto-merge → release workflow
- **`.github/skills/code-review`**: review checks specific to IssueTracker (layering, the `IMemoryCache` invalidation, model/fake/repository drift, `[Authorize]` policies, `-warnaserror`, workflow rules).
- **`blog.instructions.md`**: front matter for the generated posts in `docs/blogs/`.

**Rewritten for IssueTracker**
- `blazor.instructions.md` (Blazor Server via `_Host.cshtml`, code-behind, `@inject`, Radzen + Bootstrap, Azure AD B2C, DTO-bound forms), `dotnet-project.instructions.md`, and `git-commit-instructions.md` (IssueTracker scopes and examples, fixed code fences).
- `markdown.instructions.md` now uses **one H1 title per file**, resolving the MD041 conflict Copilot flagged on #140.

**Removed**
- `copilot-instructions.md` (both copies), all 14 prompts, and 9 skills written for other repos. That includes `bunit-test-migration`, which targets bUnit's 1.0 beta API; IssueTracker never used it. The `TestContext` → `BunitContext` migration will get its own guidance.

**Kept:** `mongo-dba.instructions.md` (long line wrapped).

markdownlint now covers `.github/` too; the temporary ignores from #140 are gone.

### Checked against the code

While writing this I checked each claim against the code, and corrected these:
- Services cache in `IMemoryCache`, not Redis.
- `Architecture.Tests` only enforces part of the layering; the rest is convention.
- The UI project references PlugIns for two things: DI registration in `Extensions/`, and the MongoDB health probe in `Helpers/MongoHealthCheck.cs`.
