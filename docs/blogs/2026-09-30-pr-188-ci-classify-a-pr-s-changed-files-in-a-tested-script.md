# ci: Classify a PR's changed files in a tested script

- **Release tag:** `v0.0.20`
- **Source PR:** [#188](https://github.com/mpaulosky/IssueTracker/pull/188)

## PR description

### Summary

The docs-only skip (#175) decided inline, in `ci.yml`'s shell, whether a PR skips the build and tests. That rule decides whether required checks run, yet it had no automated tests. Copilot asked for them on the port to mpaulosky/atelier-store#95, so the rule now lives in a tested script here too, keeping this reference in step.

- **`.github/scripts/detect_changes.py`** lists the changed files (`git diff --name-only --no-renames -z` against the base) and appends `code=true` or `code=false` to `$GITHUB_OUTPUT`. The rule is unchanged: docs-only when every path is under `docs/` or ends in `.md`; anything else, or an empty diff, runs the build. `-z` keeps file names with spaces or line breaks whole, and git's output is decoded by hand, because `text=True` would turn a `\r` in a name into `\n`. The first code path is logged with `\r` and `\n` escaped, so a file name can't start a workflow command such as `::error::` on the next log line.
- The `Detect Changes` step keeps its push and manual-run shortcut and calls the script for pull requests. The job now matches atelier-store's exactly.

### Testing

- New `test_detect_changes.py` (23 tests) builds real git repos: docs-only, code, mixed, an empty diff, code moved into `docs/`, code renamed to `.md`, a deletion, file names with spaces and newlines, and a code path whose name holds `\n::error::` and `\r::warning::` (logged on one escaped line), plus each path's classification and the output line the job reads. All script tests: 181 passed, 1 skipped.
- The same script runs live in atelier-store: #95 itself ran the build, and its docs-only blog PR (mpaulosky/atelier-store#98) skipped the build and tests and merged in about 1.5 minutes under `main`'s ruleset.
- `yamllint`, `actionlint` and `zizmor` are clean, and the pre-push gate passed.
